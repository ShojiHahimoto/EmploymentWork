モーション：キーから1フレームの姿勢へ

Quaternion、補間、FK、バインド姿勢、スキニングの関係を理解します。

時刻と回転キー
→
SampleBoneTrack
時刻の姿勢を補間
→
SkeletonPose
各骨のローカル変換
→
FK
親から子へ行列を合成
→
スキニング行列
頂点を変形

保存するキーフレームは、描画用の全頂点ではありません。各部位の回転などを保存し、表示したい時刻でその間を補間します。Quaternionは回転の表現、FKは親子の変換を伝える計算、スキニングは骨の変換を頂点へ反映する処理です。それぞれ役割が違います。

用語直感的な意味現行実装で見る場所
バインド姿勢モデルが持つ基準の姿勢。Tポーズと同義とは限らない。ModelResourceの骨情報
ローカル回転親の座標系に対する回転。SkeletonLocalPose / Quaternionキー
FK肩の回転を肘・手へ順に伝える。MotionPose::UpdateSkinningMatrices
Slerp二つの回転の間を球面上で補間する。MotionPoseのトラック評価
スキニング頂点のボーン重みで複数の骨の影響を合成する。ModelSkinnedシェーダとRenderer
意味上の部位名RShoulderなどツールの15部位。MotionSkeletonDefinition
実FBXの骨補助骨を含む実際の親子階層。15個とは限らない。ModelResourceの全骨配列

ローカル行列はスケール・回転・平行移動の順に組み立て、親の行列へつなぎます。このコードは行ベクトル側の合成順を使っています。別の数学資料の列ベクトル式をそのまま転記してはいけません。

boneWorldMatricesという名前ですが、ここで組み立てるのはモデル内部の階層行列です。オブジェクト全体のWorld行列は別に掛けます。

スキニング用行列ではoffsetMatrixを掛け、元の頂点を骨の基準から現在姿勢へ移せる形にします。

全身キーと部位トラック

UI上では全身単位でキーを追加しますが、MotionData内部は部位ごとのトラックです。全身追加では15部位をサンプリングして同じフレームへ書き込みます。HasMotionKeyframeは「少なくとも1部位のキーがあるか」であり、全15部位が必ず存在することを検証する関数ではありません。

12template<class Key> Key& FindOrInsert(std::vector<Key>& keys, int frame)13    {14        const auto earlier = [](const Key& a, const Key& b) { return a.frame < b.frame; };15        // 過去の下書き等が未整列でも、lower_boundへ渡す前に前提を回復する。16        if (!std::is_sorted(keys.begin(), keys.end(), earlier)) std::stable_sort(keys.begin(), keys.end(), earlier);17        auto found = std::lower_bound(keys.begin(), keys.end(), frame,18            [](const Key& key, int value) { return key.frame < value; });19        if (found == keys.end() || found->frame != frame)20        {21            Key key;22            key.frame = frame;23            found = keys.insert(found, key);24        }25        return *found;26    }

template<class Key>は、frameというメンバーを持つキーなら同じ処理を使うための型パラメータです。姿勢キーと移動キーの配列に、別々の挿入処理を書かずに済みます。

earlierというラムダは2個のキーを比較します。stable_sortで未整列の下書きを修復してから、lower_boundで「frame以上になる最初の位置」を探します。

同じ時刻が見つかれば既存キーを返し、無ければその位置へ新規キーを挿入します。戻り値はKey&なので、その後の代入が配列内のキーへ直接反映されます。

vector::insertがメモリーを再確保する可能性があるため、前に得たキーへの参照を、次の挿入後まで保持しないことが重要です。

最初のキーより前と、ループのつなぎ目

描画側のSampleBoneTrackは、非ループでは基準姿勢から最初のキーへ補間します。frame+1を使うのは、編集プレビューの待機0と内部の攻撃開始0が別であるためです。ループでは末尾から先頭へ時間をまたいで補間します。

読む順序は、キーなし → ループ時刻の調整 → 前後キー探索 → ループ境界 → 非ループ先頭前 → 通常の補間です。最初から全ての枝を同時に理解しようとせず、まず「前後にキーがある普通のフレーム」を追ってください。

位置とスケールはLerp、回転はQuaternion::Slerpを使います。hasPosition/hasRotation/hasScaleは、その成分のキーが指定されているかを表し、未指定の成分はbasePoseを基準にします。

返すのは1つの骨のSkeletonLocalPoseです。この関数だけでは子の位置もGPUの頂点も更新されません。その後のFKとスキニングが必要です。

同じ「補間」でも別実装がある

MotionEditor内のGetMotionRotationQuaternionAtFrameは、先頭キーより前で先頭の回転を返します。MotionPoseの基準姿勢からの補間とは違います。キー追加・表示用のサンプル値と実描画の一致を変更する際は、この二つを比較する必要があります。資料では同一処理と扱いません。

Euler表示とQuaternion保存

UIの角度は人が読みやすいEulerですが、回転キーの正本はQuaternionです。Eulerへ分解してから毎回Quaternionへ戻すと、同じ回転の別表現を跨ぐ場所で値や制限が跳ねることがあります。Gizmoの回転結果はQuaternionのまま適用し、数値表示用の変換とは分けています。左右対称の表示符号の変換も、保存済み回転を一斉反転する処理ではありません。

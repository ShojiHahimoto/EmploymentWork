平行移動の目標、固定長の骨、到達限界、制限の連続性を理解します。

位置目標は保存しない

手首を移動する操作でも、骨を伸縮したり手首のローカル位置を直接保存したりはしません。肩と肘の回転を変え、その結果として手が指定位置へ近づきます。「回転で解く」ことと「手が円を描いてよい」ことは違います。目標は開始位置から要求位置へ向かう直線上で扱います。

二つの骨の長さを保つ計算

量意味
a / b上腕・前腕など2本の長さ。
d根元から目標までの距離。
|a−b| ≤ d ≤ a+b長さを変えずに届く距離の範囲。
along = (a²−b²+d²)/(2d)根元から目標方向へ測った肘の投影位置。
height = √(a²−along²)その直線から肘が離れる量。
pole肘をどちら側へ曲げるかを示す方向。開始姿勢から安定した側を選ぶ。

目標を単に球面へ押し戻すと、カーソルは直線でも手は円弧へ曲がることがあります。現在のReachFractionは、開始点から要求点への線分と到達領域の境界を求め、その線分上で止める考え方です。到達不能な要求まで無理に動かすことはしません。

制限に当たったら、無理に別解へ飛ばさない

Solveは開始姿勢を基準に、目標まで段階的に解を調べます。まず既存の曲がり側に近い解を試し、必要ならねじり方向や軸合わせの候補を比較します。制限や連続性を満たさない境界では二分探索を行い、最後に成立した位置を採用します。これが「到達できるなら移動、できないなら手前で止める」の具体的な仕組みです。

処理なぜ必要か
開始姿勢を固定して解く毎回前回の誤差を新しい基準にすると、ドラッグ中にねじれが蓄積しやすい。
Quaternionの連続性を検査近い目標でも大きく異なる別解へ飛ぶのを避ける。
通過中の制限も確認終点が有効でも途中で可動域を突き抜ける経路を採用しない。
末端のローカル回転を維持手首・足首を無理に世界向き固定しない。親の回転に合わせて世界向きは変わり得る。
対象の骨経路だけFK更新各候補で全骨のスキニングを再計算する負荷を避ける。

可動域の表現はEulerのクランプではない

MotionRotationLimitsでは基準回転に対する相対回転を、ねじりと振りに分けます。QuaternionのY成分とwからねじりを取り出し、残りを振りとして評価します。開発者向けの制限値は度数で読めても、基本計算を毎回Euler3軸へ分解しているわけではありません。

Trace

34template<class Sample> float Trace(MotionBodyPart part, const Quaternion& start, const Quaternion& bind, Sample sample)35    {36        auto allowance = MotionRotationLimits::Measure(part, start, bind, start);37        float previous = 0;38        for (int step = 1; step <= 180; ++step)39        {40            const float t = float(step) / 180;41            auto value = MotionRotationLimits::Measure(part, sample(t), bind, start);42            if (!MotionRotationLimits::Permits(value, allowance))43            {44                float low = previous, high = t;45                for (int i = 0; i < 18; ++i)46                {47                    const float middle = (low + high) * 0.5f;48                    if (MotionRotationLimits::Permits(MotionRotationLimits::Measure(part, sample(middle), bind, start), allowance)) low = middle;49                    else high = middle;50                }51                return low;52            }53            for (size_t i = 0; i < value.size(); ++i) allowance[i] = std::min(allowance[i], value[i]);54            previous = t;55        }56        return 1;57    }

sampleは「経路上の割合tを渡すと回転を返す関数」です。回転の進め方そのものを引数で受け取るため、Slerp経路にもGizmoの単軸回転経路にも同じ制限探索を使えます。

最初に開始姿勢の違反量をallowanceへ入れます。各段階が許容される間は前へ進み、最初に許容されなくなった区間だけ二分探索します。low側が最後に成立した割合です。

allowanceをminで減らすのは、すでに制限外だった姿勢が改善した後、元の悪い状態まで再び進むことを許さないためです。

開始姿勢がすでに制限外の場合、即座に範囲内へ跳ばすと編集開始時に姿勢が崩れます。現行処理は初期の違反量を許容量として扱い、その量を悪化させない方向へ進めます。いったん改善した違反を再び増やさないよう許容量も更新します。

現在できることを過大に説明しない

MotionIkのチェーン定義にはtranslationLockedの対象があります。手足の標準2ボーン解法と、肩・股関節・肘・膝に期待する全身連動は同じではありません。15部位だけで、反対側の位置と姿勢を完全固定したまま任意の平行移動ができると説明するのは誤りです。実際に有効なチェーン・固定指定はMotionIk.cppの定義全文を確認してください。

変更した後に確認する組み合わせ

Tポーズだけでは確認不足です。肘を曲げた姿勢、腕を上げた姿勢、左右、到達限界、可動域境界、境界から戻す操作、非一様スケールを含むモデルなどを分けます。tools/tests/MotionIkTests.cppとMotionPoseTests.cppは計算の確認用ですが、マウス感度やGizmoの当たり判定まで保証するテストではありません。

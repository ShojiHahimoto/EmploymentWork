技編集：フレームと判定を読み解く

発生・持続・硬直、硬直差、プレビューの1Fずれを数値例で理解します。

三つのフレーム表現

表現開始用途
内部actionFrame攻撃開始が0攻撃判定・キー保存・再生計算
プレビューの表示フレーム0は待機、1が攻撃開始Timelineとキャンセル設定の表示
startup何フレーム目に判定が出るか。最速2内部の判定開始はstartup−1
例：発生4、持続3、硬直7前隙持続硬直
内部actionFrame0〜23〜56〜12
プレビュー1〜34〜67〜13

GetAttackTotalFrames

Data/AttackData.h:124 · GetAttackTotalFrames の関数別解説へ

124inline int GetAttackTotalFrames(const AttackFrameData& frame)125{126	return std::max(1, GetAttackActiveEndFrameExclusive(frame) + std::max(0, frame.recovery));127}

発生は「前隙の長さ」ではなく「発生するフレーム番号」なので、合計はstartup−1 + active + recoveryです。負値に対する補正と、最低1フレームを確保する処理も入っています。

IsAttackFrameActive

Data/AttackData.h:168 · IsAttackFrameActive の関数別解説へ

168inline bool IsAttackFrameActive(const AttackFrameData& frame, int actionFrame)169{170	return GetAttackActiveFrameCount(frame) > 0171		&& actionFrame >= GetAttackActiveStartFrame(frame)172		&& actionFrame < GetAttackActiveEndFrameExclusive(frame);173}

終端を含まない範囲で判定します。例えばstart=3、active=3なら3以上6未満です。持続が0なら一度も判定を出しません。

硬直差を入力してスタンを保存する

UIの硬直差は、その技の最初の持続フレームに当たる想定です。相手が何フレーム固まるかを直接入力するのではなく、自分より何フレーム後に動けるかを入力します。実行時のスタン管理方式に合わせ、ヒットしたフレームの次から残る攻撃側フレーム数を使います。

GetAttackerRemainingFramesOnFirstActiveHit

Data/AttackData.h:134 · GetAttackerRemainingFramesOnFirstActiveHit の関数別解説へ

134inline int GetAttackerRemainingFramesOnFirstActiveHit(const AttackFrameData& frame)135{136	const int firstActiveFrame = GetAttackActiveStartFrame(frame);137	return std::max(0, GetAttackTotalFrames(frame) - firstActiveFrame - 1);138}

上の例ではtotal=13、firstActive=3なので残りは9です。硬直差0ならスタン9、+2なら11、−3なら6になります。この−1を独断で削除すると対戦側の更新タイミングとずれます。

ConvertFrameAdvantageToStunFrames

Data/AttackData.h:157 · ConvertFrameAdvantageToStunFrames の関数別解説へ

157inline int ConvertFrameAdvantageToStunFrames(const AttackFrameData& frame, int frameAdvantage)158{159	return std::max(0, GetAttackerRemainingFramesOnFirstActiveHit(frame) + frameAdvantage);160}

スタンが負にならないよう0へ丸めます。そのため極端な負の硬直差は、そのまま往復変換できるとは限りません。

キャンセル設定を隠しても値が消えない理由

AttackDataはcanAttackCancelとcancelSettingを別に持ちます。falseは「この設定を使わない」という意味で、開始・終了・種類を消す意味ではありません。UIの表示フレームは内部値+1です。保存する値は内部フレームのままです。

判定と移動は姿勢とは別

hitboxesはoffsetとsizeを持つ2Dの箱です。発生フレームは各箱に重複して保存せず、技のframeから共通に決まります。movementKeysは技開始地点からの相対移動量で、MotionDataの関節回転ではありません。編集画面では一緒に見えても、対戦でTransformを動かす性能と、骨の姿勢を変える見た目は保存先が違います。
